## 실습 — 브랜치 만들고, 합치고, 충돌 내고, 고쳐보기

오늘 배운 걸 몸으로 확인해볼 시간입니다. IntelliJ의 Git 기능만으로 아래 요구사항을 하나씩 직접 달성해보세요. (명령어는 쓰지 않습니다 — 필요한 기능은 모두 IntelliJ 우측 Git 패널과 상단 VCS 메뉴 안에 있습니다.)

### 0단계. 준비하기

- [ ]  `branch-practice`라는 이름의 새 프로젝트(또는 폴더)를 만들고, IntelliJ에서 Git 저장소로 초기화하세요.
- [ ]  `notice.txt` 파일을 만들어 `버전 1` 이라는 내용을 넣고, 첫 커밋을 남기세요.

### 1단계. `feature/` 브랜치 만들고 정상 병합하기 (Fast-forward)

- [ ]  `feature/notice-emoji` 라는 이름의 브랜치를 새로 만들고, 그 브랜치로 이동하세요.
- [ ]  `notice.txt` 내용을 `버전 1 🎉` 로 수정하고 커밋하세요.
- [ ]  `main` 브랜치로 돌아가서, 방금 만든 브랜치를 병합하세요.
- [ ]  Git 히스토리(로그)를 열어, 병합 커밋이 따로 생기지 않고 `main`이 그대로 앞으로 이동했는지(Fast-forward) 확인하세요.

### 2단계. 이번엔 두 개의 브랜치가 같은 줄을 건드리게 만들기

- [ ]  `main`에서 갈라져 나온 `feature/notice-color` 브랜치를 만들어, `notice.txt`를 `버전 1 🎉 (파란색)` 으로 수정하고 커밋하세요.
- [ ]  다시 `main`으로 돌아가, 이번엔 `feature/notice-bold` 브랜치를 만들어 `notice.txt`를 `버전 1 🎉 (굵게)` 으로 수정하고 커밋하세요.
- [ ]  두 브랜치가 같은 파일의 같은 줄을 서로 다르게 고쳤다는 걸 각 브랜치에서 확인하세요.

### 3단계. 하나씩 병합해서 충돌 직접 만나보기

- [ ]  `main`에서 `feature/notice-color`를 먼저 병합하세요. (정상적으로 병합될 것입니다.)
- [ ]  이어서 `feature/notice-bold`를 병합하세요. 이번엔 충돌이 발생합니다.
- [ ]  IntelliJ가 띄워주는 충돌 파일 화면(Merge 창)에서 `notice.txt`의 어느 부분이 충돌 중인지 찾아보세요.

- [ ]  ### 4단계. 충돌 해결하기

- [ ]  IntelliJ의 Merge 화면에서 두 버전 중 하나를 선택하거나, 둘을 적절히 합친 내용(예: `버전 1 🎉 (파란색, 굵게)`)으로 직접 수정하세요.
- [ ]  충돌을 해결했다고 표시하고, 병합 커밋을 완료하세요.
- [ ]  Git 히스토리에서 이번 병합 커밋에 부모가 두 개(3-way 병합) 연결되어 있는지 확인하세요.

### 5단계. `hotfix/` 시나리오 체험하기

- [ ]  지금 작업 중이던 브랜치는 그대로 두고, `main`에서 곧바로 `hotfix/notice-typo` 브랜치를 새로 만드세요.
- [ ]  `notice.txt`에 `오타 수정` 내용을 추가하고 커밋하세요.
- [ ]  `main`으로 돌아가 이 브랜치를 병합하세요.
- [ ]  병합된 커밋에 `v1.0.1` 같은 태그를 IntelliJ에서 직접 찍어보세요.

### 완료 체크리스트

- [ ]  Fast-forward 병합과 3-way 병합이 Git 히스토리에서 어떻게 다르게 보이는지 확인했다
- [ ]  IntelliJ의 Merge 화면에서 충돌을 직접 해결해봤다
- [ ]  `feature/`, `hotfix/` 네이밍 규칙에 맞춰 브랜치를 만들어봤다
- [ ]  배포 시점에 맞춰 태그를 찍어봤다
- [ ]  다 쓴 브랜치는 정리(삭제)했다
